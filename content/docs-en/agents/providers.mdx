# Configuring Providers

## 1. What is a Provider?

A provider is a connection to an LLM backend. GoClaw abstracts all providers behind a common interface (`Chat` / `ChatStream`), so the agent loop works identically regardless of which backend is in use.

Providers are stored in the `llm_providers` table (PostgreSQL). API keys are encrypted with AES-256-GCM before storage. Providers defined in the config file are overridden by providers with the same name in the database.

## 3. Adding a Provider

Click **Add Provider** on the Providers page.

| Field | Description |
|-------|-------------|
| Display Name | Label shown in the UI |
| Provider Name | Unique slug (e.g. `my-openrouter`) |
| Provider Type | Connection type: `openai_compat`, `anthropic`, `claude_cli`, `acp`, `chatgpt_oauth` |
| API Key | Authentication key — encrypted AES-256-GCM on save |
| API Base URL | Custom URL (only needed for OpenAI-compat with a custom endpoint) |
| Enabled | Enable/disable provider. Disabled providers cannot be used by agents. |

After filling in the fields, click **Save**. The provider appears in the list and can be selected when creating an agent.

### Verifying the Connection

In the create/edit agent dialog, the **Check** button sends a small request to the provider with the selected model. Results:
- Green: model is valid, connection successful
- Red: authentication error or model not found

---

## 4. Selecting a Model for an Agent

After selecting a provider, the model dropdown loads the list from `GET /v1/providers/{id}/models`.

- Select from the list or type a model name directly (Combobox)
- If the provider does not return a model list, type the name manually and use **Check** to confirm
- **Fallback**: if the provider is not found, the system uses the first provider in the registry

## 5. Extended Thinking

Extended Thinking lets the LLM generate internal "reasoning tokens" before responding — improving quality on complex tasks at the cost of additional tokens and latency.

### Thinking Levels

| Level | Description |
|-------|-------------|
| `off` | Disabled (default) |
| `low` | Light, fast thinking |
| `medium` | Balance between speed and quality |
| `high` | Deepest thinking, for complex tasks |

### Provider Support

| Provider | Supported | Budget Tokens (low/medium/high) | Notes |
|----------|-----------|----------------------------------|-------|
| Anthropic | Yes | 4K / 10K / 32K | Strip temperature; requires anthropic-beta header |
| OpenAI-compat (GPT-5/Codex) | Yes | Via `reasoning_effort` | Capability-aware |
| DashScope (Qwen3) | Yes (some models) | 4K / 16K / 32K | No streaming when tools are present |
| Ollama / Groq / DeepSeek | No | — | Requests sent normally |

### Configuration in the Web UI

In the agent's **Config** tab, under **Thinking**:

1. **Inherit** — use provider defaults (`settings.reasoning_defaults`)
2. **Custom** — set a custom level for this agent

**Expert Mode** (when supported by provider): choose `reasoning_effort` in detail (`auto`, `minimal`, `xhigh`, etc.) and fallback behavior (`downgrade`, `off`, `provider_default`).

## 6. Provider Quotas

GoClaw tracks usage quotas for ChatGPT OAuth providers (`chatgpt_oauth`). On the Providers page:

- Green badge: number of providers successfully signed in
- Quota bar: remaining requests (per hour/day/week)
- Providers not signed in show `needs_sign_in` status

Request limits are configured via **Config > Quotas** in tenant settings. Per-agent limits can be set via Tool Policy in the Permissions tab.

## 7. Provider Pool (Multiple Accounts)

For `chatgpt_oauth`: add multiple accounts and pool them for load balancing.

**Configure the pool on the primary provider (owner):**
```json
{
  "settings": {
    "codex_pool": {
      "strategy": "round_robin",
      "extra_provider_names": ["codex-work", "codex-personal"]
    }
  }
}
```

| Strategy | Description |
|----------|-------------|
| `primary_first` | Always use the primary account first, fall back to secondary on error |
| `round_robin` | Rotate evenly among all accounts in the pool |
| `priority_order` | Try primary first, then drain secondary accounts in order |

## 8. Editing and Deleting Providers

### Edit a Provider

Click a provider in the list to open **Provider Detail**. You can edit:
- Display Name, API Key, API Base URL
- Enabled/Disabled
- Advanced settings (reasoning defaults, pool config) via the **Advanced** dialog

**Note:** Renaming a provider (`name`) breaks the connection for agents currently using it. Update agents before renaming.

### Delete a Provider

Click the delete icon on the provider row. The system requires confirmation by typing the provider name. Deleting a provider does not delete agents — agents will fall back to the first provider in the registry.
