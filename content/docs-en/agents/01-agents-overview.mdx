# Agents Overview

## Overview

An agent is an AI assistant configured with a specific personality, knowledge, and set of tools. GoClaw supports multiple agents running in parallel, each with its own isolated workspace and independent processing loop.

---

## What Is an Agent

An agent is an independent AI entity configured with:

- **Personality and introduction** (SOUL.md, IDENTITY.md): Voice, style, name, emoji
- **Foundation knowledge** (AGENTS.md, TOOLS.md): How to operate, available tools
- **User profile** (USER.md): User's name, timezone, preferences
- **Skills and tools**: Extended capabilities for performing specific tasks

Each agent runs the **Think -> Act -> Observe** loop (up to 20 iterations) until it produces a final response.

---

## Two Agent Types

### Open Agent

- Each user has a **completely separate context** (6 files: AGENTS.md, SOUL.md, TOOLS.md, IDENTITY.md, USER.md, BOOTSTRAP.md).
- Personality and skills can be customized individually per user.
- Suitable when each person needs a different personalized AI assistant.

### Predefined Agent

- **Shared personality** for all users (SOUL.md, IDENTITY.md, AGENTS.md at the agent level).
- Each user has their own USER.md so the agent remembers personal information.
- USER_PREDEFINED.md provides common user handling rules.
- Suitable when a consistent, standardized AI assistant is needed (e.g. a customer support bot).

| Characteristic | Open | Predefined |
|---------------|------|-----------|
| Context | Fully separate | Shared personality, separate profile |
| Customization | Full | USER.md only |
| Use case | Personal assistant | Shared assistant |

## Selecting an Agent in Chat

- The chat sidebar has an **AgentSelector** dropdown — select an agent before creating a new session.
- Default agent is `default` if none is selected.
- The session key URL contains agent info: `agent:{agentId}:...` — switching session means switching agent.
- On external channels (Telegram, Discord, etc.), the agent is assigned when the channel is configured; users don't need to select one.

## UI — Agents Page

Route: `/agents`
Sidebar Group: Core
Access: Logged in

Displays a paginated list of all agents (card or list view), with search and filter by creator.

**Actions:**
- **Create agent** — opens create dialog
- **Delete agent** — confirm with name input
- **Re-summon** — reinitialize agent (re-runs context file generation)
- **Import/Export** — navigate to import-export page
- **View detail** — click to navigate to `/agents/:id`

**Create Agent Dialog:**

| Field | Description |
|-------|-------------|
| Emoji | Avatar icon |
| Name | Display name |
| Agent Key | Unique slug (auto-generated from name, e.g. `my-agent`) |
| Provider | Select an added provider |
| Model | Select a model or type manually + Verify |
| Type | `predefined` or `open` |
| Personality | Agent role description — used to auto-generate SOUL.md |
| Self-evolve | Allow agent to self-update SOUL.md |

The **Check & Create** button verifies the model connection before creating. Once the model is verified, the button changes to **Create**.

**Summoning Modal:** Shows real-time file progress when the agent is first initialized.
- Success: **Continue**
- Failure: **Retry** or **Close**

## Example — Create a Personal Agent

```
/agents -> + New Agent
  Emoji: "A"
  Name: "Assistant"
  Agent Key: assistant (auto)
  Provider: anthropic
  Model: claude-sonnet-4-5-20250929 -> Check OK
  Type: open
  Personality: "Personal assistant, friendly, concise"
  -> Create -> Summoning Modal -> Continue
  -> Agent "Assistant" appears in the list
```

---

## Notes

- Agent Key is the execution identifier — cannot be changed after creation.
- Agent type (open/predefined) affects workspace structure — cannot be changed after creation.
- Each agent has its own session namespace on the `web:direct` channel.
- Deleting an agent removes all associated sessions, memory, and context files.
