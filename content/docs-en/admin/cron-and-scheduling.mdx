# Cron and Scheduling

## Overview

Cron lets agents run automatically on a schedule — no manual message needed. Each cron job triggers an agent turn with a specific prompt, running in a dedicated `cron` lane (up to 30 concurrent jobs).

**List route:** `/cron` — Logged in
**Detail route:** `/cron/:id` — Logged in

---

## Guide

### 3 Schedule Expression Types

| Type | Parameter | Example | Behavior |
|------|-----------|---------|----------|
| `at` | Epoch ms timestamp | Tomorrow 15:00 | Run once, auto-delete after running |
| `every` | Interval in ms | `1800000` (30 min) | Fixed repeat |
| `cron` | 5-field expression | `"0 9 * * 1-5"` | Flexible schedule |

**5-field cron expression:** `minute hour day-of-month month day-of-week`

Common examples:
- `"0 9 * * 1-5"` — 9:00 AM on weekdays
- `"0 */6 * * *"` — every 6 hours
- `"30 8 * * 0"` — Sunday 8:30 AM

### Create a Cron Job

1. Go to **Cron > New Job**
2. Fill in the fields:
   - **Name**: descriptive name (required, auto-generates slug)
   - **Agent**: select agent to run
   - **Prompt/Message**: message content to send to the agent (required)
   - **Schedule**: select schedule type and enter value
     - `every`: interval in seconds (minimum 1)
     - `cron`: cron expression (e.g. `0 * * * *`)
     - `at`: one-time, defaults to now + 1 minute
3. Click **Create** — job starts running immediately

### Manage Jobs

**Enable/Disable:** Click the toggle on the row or in the job detail. Disabled jobs are skipped during periodic checks.

**Delete:** Click **Delete** on the row, confirm before deletion. `at` jobs auto-delete after running.

**Manual Trigger:** Go to job detail > click **Run Now** — use to test before setting the official schedule.

**Run History:** Go to job detail > view **Run Log** — run time, execution duration, status, output, and error messages. System keeps up to 200 records.

### Advanced Settings (Job Detail)

- **Timezone**: IANA timezone (default UTC)
- **Delivery**: Send to Channel (switch) — select Channel + Recipient; Wake Heartbeat (switch)
- **Lifecycle**: Delete After Run (switch); Stateless (switch)

## UI

### List Page (`/cron`)

**Displays:** Paginated list of all jobs with search: status, schedule, next run, last run.

**Actions:** Create job | Run now | Delete | View detail | Refresh

**Create Job Dialog:**
- Fields: Name (required), Agent ID, Schedule type (button group: every/cron/at), Message (required)
- Actions: **Create** | **Cancel**

### Detail Page (`/cron/:id`)

**Displays:** Schedule, payload, target agent, run history, enable/disable status.

**Actions:** Run now | Enable/disable | Update settings | Delete | View run log

**Run Log Dialog:** Scrollable list — time, status badge (green/red), summary, error. Empty state: "No run history".

**Advanced Settings Dialog:** Timezone, Delivery, Lifecycle. **Save** | **Cancel**

## Lane-Based Concurrency

| Lane | Default Concurrency | Override Env |
|------|:-------------------:|--------------|
| `main` | 30 | `GOCLAW_LANE_MAIN` |
| `subagent` | 50 | `GOCLAW_LANE_SUBAGENT` |
| `team` | 100 | `GOCLAW_LANE_TEAM` |
| `cron` | 30 | `GOCLAW_LANE_CRON` |

Cron jobs do not compete for resources with chat sessions. Jobs sharing the same session are queued sequentially to prevent race conditions.

---

## Automatic Retry

| Parameter | Value |
|-----------|-------|
| Max retries | 3 |
| Initial delay | 2 seconds |
| Max delay | 30 seconds |

Formula: `delay = min(2 x 2^attempt, 30)` +/- 25% jitter.

## Real-World Examples

**Daily report:**
- Type: `cron`, Expression: `"0 8 * * 1-5"`
- Agent: Analyst Agent
- Prompt: *"Generate a system activity report for the past 24 hours and send a summary to the #reports channel"*

**Periodic health check:**
- Type: `every`, Interval: `1800000` (30 minutes)
- Agent: Monitor Agent
- Prompt: *"Check the status of main services, report any anomalies detected"*

## Notes

- `cron` lane supports up to 30 concurrent jobs
- `at` jobs are auto-deleted after running — no manual cleanup needed
- Use **Run Now** to test before setting the official schedule
