# Tools and MCP Servers

## Overview

GoClaw has a system of built-in tools grouped by category, and supports registering MCP servers to extend agent capabilities. Tool access is controlled through multi-layer profiles and policies.

**Built-in tools route:** `/builtin-tools` — Admin
**MCP servers route:** `/mcp` — Admin

---

## Guide

### Built-in Tool Profiles

4 profile levels define which tools an agent is allowed to use:

| Profile | Tools Included |
|---------|----------------|
| `minimal` | Only `session_status` |
| `messaging` | messaging, web, sessions, media_read, skill_search |
| `coding` | fs, runtime, sessions, memory, web, knowledge, media_gen, media_read, skills |
| `full` | All registered tools |

**Configuration:** Agents > select agent > Tools tab > select profile. Can override profile per LLM provider.

### Exec Approval

Controls whether agents can run shell commands:

**Security Mode:**

| Mode | Behavior |
|------|----------|
| `deny` | Block all shell commands |
| `allowlist` | Only accept commands matching glob patterns in the allowlist |
| `full` | Allow all commands (default) |

**Ask Mode:**

| Mode | Behavior |
|------|----------|
| `off` | Auto-approve — no prompt (default) |
| `on-miss` | Prompt when command is not in the allowlist |
| `always` | Prompt before every command execution |

When prompted: request sent to admin, 2-minute timeout. Admin chooses: **Allow once** | **Allow always** | **Deny**.

Commands blocked regardless of mode: `rm -rf`, `curl|sh`, reverse shells, fork bombs, ...

**Configuration:** Settings > Config > exec, or per-agent in Agents settings.

### Custom Tools

Create tools from shell commands without recompiling or restarting:

1. Go to **Settings > Custom Tools > Add Tool**
2. Fill in the fields:
   - **Name**: tool name (used in LLM tool calls)
   - **Description**: description so LLM knows when to use it
   - **Parameters**: JSON Schema for parameters
   - **Command**: shell command, use `{{.param_name}}` for parameters
   - **Timeout**: default 60 seconds
   - **Scope**: Global (all agents) or per-agent
3. **Environment Variables**: stored encrypted with AES-256-GCM, injected into the process at runtime

Example: `dig +short {{.record_type}} {{.domain}}`

Security: parameters are shell-escaped, deny patterns from `exec` tool apply, env vars are never shown in plain text.

### Web Fetch Policy

Controls which URLs an agent is allowed to fetch:

| Mode | Behavior |
|------|----------|
| `allow_all` | Allow fetching any URL (default) |
| `allowlist` | Only allow domains in `allowed_domains` |

**Configuration:** Settings > Builtin Tools > web_fetch > Settings.

### Register an MCP Server

1. Go to **Settings > MCP > Add Server**
2. Fill in:
   - **Name**: identifier (creates tool prefix: `mcp_{name}_{tool}`)
   - **Transport**: stdio / sse / streamable-http
   - **Command** (stdio): e.g. `npx -y @modelcontextprotocol/server-filesystem /workspace`
   - **URL** (sse/http): endpoint URL
   - **Environment Variables**, Timeout, Enabled, Require user authentication
3. Click **Test Connection** > **Create/Update** | **Cancel**

Health check: every 30 seconds. Reconnect: exponential backoff (2s → 60s max, 10 retries).

### MCP Grants — Access Control

**Grant access to an Agent:**
1. MCP > select server > Grants
2. Select agent, optionally add Tool Allow / Tool Deny list
3. Click **Grant** / **Revoke**

**Grant access to a User:** Same as above but applied to a specific user.

Rule: deny > allow. A denied tool will not appear even if on the allow list.

### MCP Self-Service

Users can request MCP server access themselves:
1. User submits request via Web UI or API
2. Request is in `pending` state — admin receives notification
3. Admin goes to **MCP > Pending Requests** > **Approve** or **Reject**
4. Grant takes effect immediately after approval

## UI

### Built-in Tools Page (`/builtin-tools`)

**Displays:** All tools grouped by category. Each tool: display name, code name, description, requirement badge, deprecation badge.

**Categories:** filesystem, runtime, web, memory, media, browser, sessions, messaging, scheduling, subagents, skills, delegation, teams.

**Actions:** Enable/disable toggle per tool | Configure settings (dialog) | Organization override | Reset override | Search | Refresh

> Warning shown when enabling media tools without a configured provider.

### MCP Servers Page (`/mcp`)

**Displays:** MCP integration table: name, transport type, tool count, agent count, status, creator.

**Actions:** Add MCP server | Edit | Delete | Reconnect | Manage agent grants | View tools | Manage user authentication

**MCP Form Dialog:**
- Fields: Name, Display Name, Transport (stdio: command+args | SSE/HTTP: URL+headers), Environment Variables, Tool Prefix, Timeout, Enable/Disable, Require Authentication
- Actions: **Test Connection** | **Create/Update** | **Cancel**

**Agent Grant Dialog:** List of existing grants + grant form: select agent, allow/deny lists (multi-select with search). **Grant/Update** | **Revoke** | **Cancel**

**View Tools Dialog:** Scrollable list with search filter — name, description, prefix badge (read-only).

**User Authentication Dialog:** Select user, API Key, Headers (sensitive hidden), Environment Variables. **Save** | **Delete All** | **Cancel**

## Tool Policies — 7 Filter Layers

1. Global profile (full/coding/messaging/minimal)
2. Provider profile override
3. Global allow list
4. Provider allow override
5. Agent allow list
6. Agent + Provider allow
7. Group allow list

Then apply deny list (global, agent), finally apply alsoAllow. Reference tool groups: use `group:` prefix, e.g. `group:fs`, `group:web`.

---

## Notes

- MCP Transport `stdio`: starts a local process; `sse`/`streamable-http`: connects to a URL
- Default tool prefix: `mcp_{server_name}_{tool_name}`
- Slack channel has its own SSRF protection: only allows downloads from `*.slack.com`
