# Sessions

A **session** is a conversation thread between a user and an agent. Each session maintains its own message history, context, and state.

---

## 1. Session Keys

Session keys uniquely identify a conversation:

```
agent:{agentId}:{channel}:direct:{userId}
```

- Each agent has its own session namespace
- Each user per channel gets a separate session by default
- Switching agents means switching sessions

---

## 2. Session List

The sidebar in the Chat view lists all your sessions sorted by last activity. Click any session to load its message history.

Sessions can also be listed programmatically:
- WebSocket: `sessions.list`
- HTTP: `GET /v1/sessions`

---

## 3. Session Scope Configuration

Session scoping is controlled by `sessions.scope` in `config.json`:

| Value | Behavior |
|-------|----------|
| `per-sender` | Each sender gets their own session (default) |
| `global` | All users share a single session per agent |

The `dm_scope` setting controls how DM sessions are keyed:

| Value | Behavior |
|-------|----------|
| `main` | All DMs share one session |
| `per-peer` | Each peer gets their own session (shared across channels) |
| `per-channel-peer` | Each (channel, peer) pair gets its own session (default) |
| `per-account-channel-peer` | Adds the bot account to the key for isolation |

---

## 4. Context Window & Summarization

When the session's message history approaches the context window limit (>85% of tokens), GoClaw automatically summarizes older messages to make room for new ones.

Before summarizing, the agent is prompted to save any important memories to its `MEMORY.md` file in the workspace.

---

## 5. Resetting a Session

To clear all messages from a session without deleting it:
- WebSocket: `sessions.reset`
- Telegram: `/reset` command

This removes the full message history but keeps the session key active.

---

## 6. Deleting a Session

To permanently delete a session and all its messages:
- **Web UI** — hover over the session in the sidebar, click the delete icon, confirm
- **WebSocket** — `sessions.delete`

Deleted sessions cannot be recovered.

---

## 7. Read-Only Sessions

If a session belongs to another user, the Web UI displays it as read-only with the banner:

> "Read-only — this session belongs to another user"

Admins can view other users' sessions but cannot send messages to them through the UI.

---

## 8. Session Metadata

Sessions can be labeled and updated:
- WebSocket: `sessions.patch` — update label, model override, metadata

This is useful for organizing long-running conversations or tracking context across multiple chats.
