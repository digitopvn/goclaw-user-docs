# Channels

GoClaw supports 7 messaging channels to connect AI agents with popular platforms.

---

## 1. Overview — 7 Channels

| Channel | Connection Type | Groups | DMs | Streaming |
|---------|----------------|--------|-----|-----------|
| Telegram | Long polling | Yes | Yes | Typing indicator |
| Discord | Gateway events | Yes | Yes | Edit "Thinking..." |
| Slack | Socket Mode (WebSocket) | Yes | Yes | Edit "Thinking..." |
| Feishu/Lark | WebSocket / Webhook | Yes | Yes | Streaming card |
| Zalo OA | Long polling | No | Yes | No |
| Zalo Personal | Internal protocol (unofficial) | Yes | Yes | No |
| WhatsApp | External WebSocket bridge | Yes | Yes | No |

Each channel runs independently. Each user on each channel gets their own isolated session.

---

## 2. Chatting via Telegram

- **DMs** — Send a direct message to the bot; processed immediately
- **Groups** — The bot must be `@mentioned` before it replies (default). Messages before the mention are retained as context (up to 50 messages)
- **Implicit reply** — Replying to the bot's message in a group counts as a mention
- **Voice/Audio** — Voice messages are transcribed via STT proxy; content is prefixed with `[audio: filename] Transcript: ...` before being sent to the agent
- **Forum topics** — Each topic in a supergroup has its own session and configuration
- **Bot commands** — `/stop` cancels the current run, `/stopall` cancels all, `/reset` clears history, `/help` shows help

---

## 3. Chatting via Discord

- **DMs** — Send a direct message to the bot
- **Channels** — Bot requires `GuildMessages` + `MessageContent` intents; must be `@mentioned` (default)
- **Streaming** — Bot sends a "Thinking..." message and edits it when the response is ready
- **Limit** — 2,000 characters per message; automatically split if exceeded
- **Typing indicator** — Keepalive every 9 seconds while the agent processes

---

## 4. Chatting via Slack

- **DMs** — Send a direct message to the bot
- **Channels** — Must `@mention` the bot; once it replies in a thread, subsequent messages in that thread activate the bot without mentioning (TTL 24 hours)
- **Socket Mode** — WebSocket connection — no public URL required
- **Streaming** — Edit-in-place via `chat.update`, throttled at 1000ms (Slack Tier 3)
- **Reactions** — Emoji status reactions on user messages (thinking, using tool, done, error)
- **Limit** — 4,000 characters per message

---

## 5. Chatting via Feishu/Lark

- **DMs** — Send a direct message to the bot
- **Groups** — Requires `@mention` (default); can be disabled per channel
- **Streaming card** — Response displayed in an interactive card with live typing effect (throttled 100ms)
- **Topic session mode** — When enabled, each thread gets its own session (key: `{chatID}:topic:{rootMsgId}`)
- **Media** — Receive/send images, files, audio (default max 30 MB)
- **Connection** — WebSocket (default) or Webhook — can be mounted on the gateway's HTTP port

---

## 6. Chatting via Zalo

### Zalo OA (Official Account)

- DMs only — no group messaging
- 2,000 character limit per message
- Default DM policy: `pairing` (requires authentication code)
- Supports image sending (max 5 MB)

### Zalo Personal

- Uses an unofficial (reverse-engineered) protocol
- Supports both DMs and groups
- Default policy: `allowlist` (only accepts users on the allowed list)
- **Warning**: Account may be banned by Zalo at any time for violating terms of service

---

## 7. Pairing Flow (Device Authentication)

Applies when a channel uses the `pairing` policy for DMs:

1. A new user sends their first message — the bot returns instructions and an **8-character code** (valid for 60 minutes)
2. The user provides this code to an admin
3. Admin approves via `device.pair.approve` (Web UI or WebSocket RPC)
4. The connection is paired — subsequent messages are processed normally

Pairing code details:
- Length: 8 characters
- Alphabet: `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (ambiguous characters like 0, O, 1, I, L removed)
- Max 3 pending requests per account
- Debounce: bot will not resend instructions more than once every 60 seconds

---

## 8. Channel Policies

### DM Policies

| Policy | Behavior |
|--------|----------|
| `open` | Accept messages from anyone |
| `allowlist` | Only accept senders on the allowed list |
| `pairing` | Require device pairing before processing |
| `disabled` | Reject all DMs |

### Group Policies

| Policy | Behavior |
|--------|----------|
| `open` | Accept messages from any group |
| `allowlist` | Only accept listed groups |
| `disabled` | Do not process group messages |

Admins can enable/disable channels via `channels.toggle` (requires admin role).
